# 宠物疾病知识库/文档 GitHub 项目调研报告

## 概述

本次调研采用三段式对抗核验流程：第一阶段以 6 个 agent 并行从多维度（关键词命中、topics 标签、README 原文、仓库结构）发现候选项目；第二阶段对每个候选项目用 WebFetch 深度抓取 GitHub 仓库页与 raw.githubusercontent.com 原始 README 进行交叉印证；第三阶段由独立核验 agent 重新抓取并按"是否真实存在 / 是否确为宠物/动物疾病知识库 / 是否构成知识库或文档"三项标准做对抗审查，防止伪装执行与蹭热度命名。本轮共发现候选项目 45 个，经对抗核验通过 42 个，被反驳 3 个。以下报告均基于核验通过的 42 个项目。

### 1. [Karen0758/cat-knowledge-base](https://github.com/Karen0758/cat-knowledge-base)

- **content_summary**：英文猫咪护理知识库，基于本地 StashBase 的 cat 空间构建，面向新猫主人。提供可浏览 HTML 手册与原始兽医参考 PDF，按护理任务组织内容，涵盖喂养、家庭环境、医疗预防、老年护理、行为、疼痛管理、泌尿疾病、FIP 及人畜共患病等专题，并含 StashBase 生成的检索抽取文件。
- **disease_coverage**：猫。FIP（猫传染性腹膜炎）、泌尿结石与泌尿疾病、疼痛管理、人畜共患病风险、疫苗接种、口腔健康、麻醉、老年猫监测与肌肉状况评估、生活质量评估、治疗性饮食、NSAID 用药。
- **knowledge_base_type**：混合（文档库为主：HTML 手册 + PDF 兽医参考；含 StashBase 结构化抽取元数据与检索文件）。
- **readme_excerpt 摘要**："# Cat Parent Knowledge Base — An English cat-care knowledge base built from a local StashBase cat space. Collects feline care guidelines, veterinary reference PDFs..."（关键100字：英文猫护理知识库，含兽医参考PDF与HTML手册，按喂养/疫苗/老年护理/泌尿疾病/FIP/人畜共患病组织）
- **verify_evidence**：独立 WebFetch 两处来源互相印证。(1) 仓库页非 404，About: "An English cat-care knowledge base built from StashBase, with a handbook and veterinary reference PDFs."；正文含 "feline care guidelines, veterinary reference PDFs"、"Urinary stones, therapeutic diets, FIP diagnosis, NSAID use, and zoonotic risk"、"It does not replace veterinary diagnosis or treatment."。(2) 独立抓取 raw README 成功，标题 "# Cat Parent Knowledge Base"，知识领域覆盖 feeding, vaccination, senior care, urinary stones, FIP, zoonotic risk；含版权提示与医疗免责声明。仓库根目录含 .stashbase/、index/、README.md、STASHBASE.md、index.html，符合知识库/文档形态。

## 调研方法与防伪装执行说明

### 三段式流程

1. **并行发现阶段**：6 个 agent 从不同关键词组合（pet/dog/cat/veterinary/disease/knowledge base 等英文与中文变体）与 GitHub 搜索维度并行发现候选项目，初步汇总候选清单。
2. **WebFetch 深采阶段**：对每个候选项目用 WebFetch 抓取两类来源——GitHub 仓库页（github.com/<owner>/<repo>）与原始 README（raw.githubusercontent.com/<owner>/<repo>/<branch>/README.md），交叉印证仓库真实存在、README 原文内容、About 描述、Topics 标签、语言构成、license、star/fork/commit 数等字段。
3. **独立对抗核验阶段**：由独立核验 agent 重新执行 WebFetch，按三项标准审查：(a) 仓库是否真实存在（非 404）；(b) 是否确为宠物/动物疾病知识库（关键词命中 veterinary/pet/dog/cat/disease/health/symptom/diagnosis 等，或语义明确指向动物疾病领域）；(c) 是否构成知识库/文档/数据集/诊断工具（排除蹭热度命名但内容无关的项目）。

### sources_fetched 机制

每个项目的 verify_evidence 字段记录了实际抓取的来源 URL 与 fetch_status（success/fail），确保每条结论可追溯至原始抓取记录。抓取失败的字段标记为 insufficient data，表格中以"—"呈现，不编造数字。例如 Weixin07/PR-Veterinary-Diagnosis-System 的 README 在四个分支引用与 README.rst 均返回 404，故 readme_excerpt 标记为 insufficient data，改用 app.py 与 models.py 的 raw 抓取成功记录作为替代证据。

### 限速规避

WebFetch 抓取 raw.githubusercontent.com 的原始 README 不消耗 GitHub REST API 配额（60 次/小时限速），因此可对每个候选项目做两轮以上独立抓取而不触发限速。GitHub 仓库页（github.com）亦为普通网页抓取，不走 API。仅在需要 star/fork/commit 等结构化元数据时读取页面渲染值（部分页面仅给出相对时间如"last updated 11 minutes ago"而无绝对日期，此类字段标记为 insufficient data）。
