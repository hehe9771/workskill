## 2. 重点新特性详解

### 2.1 `/diff` 全屏 diff 面板（v2.1.260）★

**含义**：全屏模式新增 diff 面板，随 Claude 编辑实时显示未提交更改，`/diff` 开关；同时 `/cost` 与状态栏 `prompt_cache` 字段新增**缓存未命中的可能原因**（工具定义或系统提示已变、闲置超过 TTL 等）。

**与本机关系**：✅ 双重受益。本机重度全屏 + 状态栏用户，diff 面板提升编辑可见性；缓存未命中原因显示对代理环境（DashScope）排查 token 成本波动极有用——本机 prompt caching 是否生效从此有诊断依据。

### 2.2 子 agent 模型控制收紧：`CLAUDE_CODE_SUBAGENT_MODEL` 语义变化 + `_FORCE`（v2.1.251 / v2.1.257）★★

**含义**：
- v2.1.251 起 `CLAUDE_CODE_SUBAGENT_MODEL` 从"覆盖一切"改为**默认值**：agent 定义的 `model:` frontmatter 和逐次 spawn 显式指定的模型**优先级更高**
- v2.1.257 新增 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`：强制把 `CLAUDE_CODE_SUBAGENT_MODEL`（或主模型）应用到**每一个** subagent，忽略一切覆盖

**与本机关系**：✅✅ 本机硬性约束"禁止指定模型 ID（部署环境 400: model is not supported）"。升级后若 skill/agent 定义带 `model:` 字段，subagent 会绕开本机映射直连不存在的模型 ID。**升级时必须同时设 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`**（见 §7.3）。

### 2.3 Task 跟踪工具改模型白名单（v2.1.268）★★

**含义**：TaskCreate/TaskGet/TaskUpdate/TaskList、TodoWrite 只在 Claude 3.x、Opus 4.0–4.7、Sonnet 4.0–4.6、Haiku 4.5 上提供；**其他模型需设 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 恢复**。

**与本机关系**：✅✅ 本机主模型为 `ZHIPU/GLM-5.3-Flash`（第三方模型，不在白名单）。不设该变量则升级后任务跟踪工具直接消失。**升级时必须加此环境变量**。

### 2.4 `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（v2.1.269）★

**含义**：动态 Workflow 每次运行的并发 agent 上限可调（1–256）。

**与本机关系**：✅ 本机 `CLAUDE_CODE_WORKFLOWS=1` 且实测遇过并发派发丢写入问题（memory ua-incremental-pitfalls 的根因之一即并发过高）。可显式调低并发提高稳定性，或调高加速批处理。

### 2.5 agent frontmatter `omitClaudeMd`（v2.1.271）★

**含义**：subagent 可声明不加载用户/项目/本地 CLAUDE.md（托管策略文件仍加载）。

**与本机关系**：✅ 本机全局 CLAUDE.md 篇幅大（行为准则+ECC 规则），跑纯机械型子 agent（批量重命名、格式扫描等）时省去重复注入，直接省 token。

### 2.6 `/skill-doctor` + 输出上限设置（v2.1.261）★

**含义**：`/skill-doctor` 列出未使用技能及其上下文成本；`bashOutputMaxChars`/`taskOutputMaxChars` 控制内联命令/后台任务输出上限（最高 128K 字符）。

**与本机关系**：✅ 本机 200+ 技能、16 插件，`/skill-doctor` 可量化僵尸技能的上下文开销；输出上限可防大输出撑爆上下文（本机 `CLAUDE_CODE_MAX_OUTPUT_TOKENS=65536`，两者配合）。

### 2.7 `--restricted` 受限模式（v2.1.248）

**含义**：`--restricted`（或 `CLAUDE_CODE_RESTRICTED=1`）移除执行命令/代码的内建工具和 WebFetch，文件工具限制在工作目录内，拒绝 bypassPermissions，忽略用户/项目/本地设置文件。

**与本机关系**：⚠️ 面向"让 Claude 处理不可信内容"场景（如分析可疑文件）。本机 bypassPermissions 常规使用，日常用不上，知道有即可。

### 2.8 `--plugin-dir` 与插件 `--accept-command`（v2.1.265 / v2.1.271）

**含义**：`--plugin-dir` 直接指向插件文件夹加载（运行中增删可检测）；`claude plugin install/update --accept-command <sha256>` 用哈希确认安装命令，替代 `-y` 一把梭。

**与本机关系**：✅ update-all 技能批量更新插件时，`--accept-command` 提供了可审计的确认方式（记 hash 进日志）；`--plugin-dir` 为本地调试插件提供免安装途径。

### 2.9 跨 session 消息覆盖面扩展（v2.1.248）

**含义**：SendMessage/ListAgents 扩展到 Bedrock/Vertex/Foundry 及**禁用遥测**环境。

**与本机关系**：✅ 本机 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`（等效禁遥测路径），此前跨 session 消息在本机配置下不可用，现在可用。配合已开启的 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`，多 session 编排多一件工具。

### 2.10 其他值得关注

- **`maxEffortLevel` 设置**（v2.1.267）：可为全部 provider 设 effort 上限。⚠️ 本机 `effortLevel: xhigh` 是自己选的，无需设上限，知道有即可
- **`timeFormat`/`timeZone` 设置**（v2.1.257）：转写时间戳格式/时区可定制。✅ 中文环境 24 小时制更顺手（可选）
- **`permissions.blockReadsOutsideWorkingDirectories`**（v2.1.257 引入提示，259/271/273 连续加固）：阻止读取工作目录之外。✅ 本机 bypassPermissions 常开，此设置给"放权限但不放开读盘"提供中间档（可选）
- **`--append-subagent-system-prompt-file`**（v2.1.261）：从文件给 subagent 追加系统提示。✅ 与 `omitClaudeMd` 配合可精确控制子 agent 上下文
- **Workflow 描述瘦身**（v2.1.248）：Workflow 工具描述从约 5.7k token 降到约 1k，参考内容移入捆绑的 `workflow-authoring` 技能。✅ 每个会话固定省约 4.7k token
- **子 agent 后台命令限时移除**（v2.1.260）：subagent 启动的后台命令不再有 1 小时上限。✅ 长 ETL/构建任务不再被腰斩
- **Bash 编辑 diff**（v2.1.269，`bashEditDiffEnabled`）：Bash 工具处理文件编辑时结果附带 diff。✅ 用 sed/脚本批量改文件时可直览变化
- **`CLAUDE_CODE_MCP_STARTUP_WAIT_MS`**（v2.1.274）：首回合等待连接中 MCP 服务器的时长（0=不等）。✅ 本机 MCP 服务器多（drawio/pencil/context7/chrome-devtools/fetch…），启动等待可调
- **内存压力警告**（v2.1.274）：内存吃紧时显示警告与释放步骤。✅ Windows 长会话多 agent 场景友好
- **`PreModelSwitch`/`PostModelSwitch` hooks**（v2.1.251）：模型切换可被 hook 拦截/注记。⚠️ 本机模型固定映射，用处有限

## 3. 行为变化（影响使用习惯）

### 3.1 `CLAUDE_CODE_SUBAGENT_MODEL` 不再覆盖一切（v2.1.251）★★

**变化**：变为默认值，agent 定义 `model:` 与逐次 spawn 指定优先。

**影响**：✅✅ 本机必须配合 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` 使用，否则子 agent 可能请求不存在的模型 ID（400）。见 §2.2。

### 3.2 Task 工具按模型白名单提供（v2.1.268）★★

**变化**：白名单外模型默认移除 TaskCreate 等工具。

**影响**：✅✅ GLM-5.3-Flash 不在白名单，升级后需 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`。

### 3.3 遥测禁用/第三方 provider 安装默认启用 v2 MCP 客户端（v2.1.274）★

**变化**：Bedrock/Vertex/Foundry 及禁用遥测安装默认用 v2 MCP 客户端 + MCP 2026-07-28 协议协商；回退用 `MCP_SDK_GENERATION=v1` 或 `MCP_PROTOCOL_NEGOTIATION=legacy`。

**影响**：⚠️ 本机 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 很可能落入此路径。v2 客户端修了一堆 MCP 超时/重连问题（§5），但协议协商变化理论上可能影响个别老 MCP server；如遇 MCP 异常，先用回退变量排查。

### 3.4 词编辑键默认化，`keybindingFlavor` 失效（v2.1.261）★

**变化**：Ctrl+W 删到空白、Alt+F/Alt+D 按词边界、标点参与分词成为默认行为（前篇 §2.11 曾建议设置的 `keybindingFlavor: readline` 从此不需要也不生效）。

**影响**：✅ 类 Bash 编辑体验内置。前篇的该条建议作废。

### 3.5 `allowedMcpServers` 只管用户自加服务器（v2.1.259）

**变化**：托管 `managed-mcp.json` 里的服务器不再被该 allowlist 过滤；要屏蔽用 `deniedMcpServers`。

**影响**：⚠️ 本机无企业托管配置，无实际影响；如未来引入托管 MCP 需注意。

### 3.6 其他行为变化

- **全屏 Ctrl+L/Cmd+K 改为清屏**（v2.1.260）：等同终端 `clear`，上滚可看历史（此前双击触发 `/clear` 已在 2.1.238 移除）
- **插件/marketplace 克隆中 Git LFS 文件保留为指针**（v2.1.274）：需 `git lfs pull` 获取。⚠️ update-all 技能会重克隆市场——若某插件用 LFS 存资源，更新后可能拿到指针文件，验证步骤需留意
- **`"type": "sdk"` MCP 条目跳过并警告**（v2.1.274）：面向 Claude Desktop 连接器的配置，本机 `.mcp.json` 无此类型
- **`!` bash 模式命令在严格沙箱下也在沙箱外运行**（v2.1.260）：与手敲终端一致
- **auto mode 内联 `!` 命令遵循 default 模式权限规则**（v2.1.271）；**Monitor 监视一律有截止时间**（最多 30 分钟，`persistent` 移除）（v2.1.271）
- **项目级 `.claude/settings.json` 的 `defaultMode: "bypassPermissions"` 被忽略**（v2.1.257，仅用户级/托管/命令行有效）。✅ 本机设在用户级 `~/.claude/settings.json`，不受影响
- **非 Claude 模型默认 commit trailer 变为 `Co-Authored-By: Claude Code`**（v2.1.251）。✅ 本机 `includeCoAuthoredBy: false`，不出现
- **`/status` 的 GitHub 行改为 "Cloud sessions"**（v2.1.274）；claude.ai 同步技能命名 `anthropic-skills:<name>`（v2.1.269）
- **`/loop` 自主模式全环境可用**（v2.1.248，含 Bedrock/Vertex/禁遥测）。✅ 本机可用

## 5. 重要 bug 修复（挑本机有感项）

### 5.1 2.1.265 双回归及其修复（v2.1.266 / v2.1.268）★★ 升级必读

**问题 1**（v2.1.265 引入，v2.1.266 修复）：未记录的 `CLAUDE_CODE_USE_GATEWAY` 变量自行强制 Cloud 网关登录——`ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` 组合（**正是本机配置**）每请求失败 "Not signed in to the Cloud gateway"。
**问题 2**（v2.1.265 引入，v2.1.268 修复）：第三方 Anthropic 兼容端点（`ANTHROPIC_BASE_URL`）因 Artifact 工具输入 schema 中的正则**每回合 HTTP 400**。

**与本机关系**：✅✅ 两条全部命中本机配置。**结论：升级不要停在 2.1.265–2.1.267，直上 2.1.274。**

### 5.2 subagent 因缺 token 用量/模型 id 被误报失败（v2.1.273）★★

**问题**：sub-agent/后台 agent 最终回复缺 token 用量或模型 id 字段时被报失败、结果不送达。

**与本机关系**：✅✅ 第三方端点（DashScope/GLM）响应字段不全的概率远高于官方端点，本机子 agent"莫名失败"很可能与此相关。高价值修复。

### 5.3 "unexpected tool_use_id" 400 无限重试（v2.1.274）★

## 7. 升级建议

### 7.1 是否升级

**建议升级，且目标版本直上 2.1.274。** 理由（按价值排序）：

1. **两个回归窗口必须越过**：2.1.265 对本机配置（BASE_URL+AUTH_TOKEN）是"每请求失败"级别的坑，2.1.266/2.1.268 才修复——停在任何中间版本都不可用
2. **子 agent 稳定性**：2.1.273 修复第三方端点 subagent 误报失败；2.1.274 修复 tool_use_id 400 无限重试
3. **缓存诊断与修复**：2.1.260 缓存未命中原因 + v2.1.267 大批缓存修复，代理环境 token 成本可观测
4. **1M 上下文正确性**：resume 丢 `[1m]`（271）、压缩双倍计数（273）、压缩时机（260）
5. **Windows 专项**：260 字符路径、AppContainer 沙盒
6. 前篇（更新20260827.md §7.1）的高价值项（PowerShell 权限绕过修复、内存泄漏系列、`/cd` 即时生效等）在 2.1.224–2.1.247，本机至今未升级，一并获得

风险项均有对策：Task 工具白名单 → env 恢复；SUBAGENT_MODEL 语义 → FORCE 变量；v2 MCP 客户端 → 回退变量备用。

### 7.2 升级方法（手动，因黑名单不自动更新）

```bash
# 本机 DISABLE_AUTOUPDATER=1，daemon 不会自动更新 CLI，需手动：
npm install -g @anthropic-ai/claude-code@2.1.274

# 验证
claude --version   # 应显示 2.1.274

# 如需回滚到当前版本：
npm install -g @anthropic-ai/claude-code@2.1.223
```

> ⚠️ 禁止停留在 2.1.265 / 2.1.266 / 2.1.267：三者分别带网关登录回归或第三方 400 回归，对本机配置不可用。

### 7.3 升级后必做（本机专用清单）

1. **升级前先改 settings**（`~/.claude/settings.json` env 段新增两行，防升级后首启就踩坑）：
   ```json
   "CLAUDE_CODE_ENABLE_TODO_TOOLS": "1",
   "CLAUDE_CODE_SUBAGENT_MODEL_FORCE": "1"
   ```
2. **重启 Claude Code daemon**（插件与 CLI 新版本生效；旧会话需重启或 `/reload-plugins`）
3. `/doctor` 自检；`/status` 确认凭据显示正确（API key 在用、无 "Cloud gateway" 字样）
4. 验证 Task 工具可用（让 Claude 调一次 TaskList）；验证子 agent 正常（模型应为 `ZHIPU/GLM-5.3-Flash[1m]`）
5. 如 MCP 服务器出现连接异常，尝试 `MCP_SDK_GENERATION=v1` 回退并记录（§3.3）
6. 全部 `--settings` 变体文件（`~/.claude/setting/settings-*.json`）同步加 §7.3-1 两个变量（env 覆盖不继承坑）
7. update-all 技能黑名单保持不动；下次执行 update-all 前先落实其技能侧改进（E1 `--enable-hooks` 等，见更新报告-20260917-2259 §7）
8. 跑一次 `/skill-doctor`，按结果清理僵尸技能

### 7.4 不升级的风险

- 继续暴露在 2.1.232 已修复的 **PowerShell 权限绕过**（前篇 §5.1，安全级）
- 第三方端点 subagent 误报失败、tool_use_id 400 无限重试、MCP 超时等稳定性问题持续存在
- 长 session 内存泄漏系列（2.1.238–247）不获得，Windows 卡顿加剧
- resume 掉 1M、压缩双倍计数等上下文正确性问题持续
- 越晚升级，跨版本回归风险越大（本次 51 个版本中已出现 2 个环境适配坑，都是"升级中间版本才踩、升到最新反而无事"）
