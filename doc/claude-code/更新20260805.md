## 2. 重点新特性详解

### 2.1 Claude Opus 5 成为默认 Opus 模型（v2.1.219）

**含义**：Claude Opus 5（`claude-opus-5`）成为默认 Opus 模型，1M 上下文，fast mode 价 $10/$50 每百万 token。Opus 4.7 从 fast mode 移除。

**与本机关系**：⚠️ 本机通过 `ANTHROPIC_BASE_URL=https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic` 走阿里云 token-plan 代理，实际模型为 `qwen3.8-max-preview[1M]`，并非官方 Opus。**此特性对本机无直接效果**——本机已拥有 1M 窗口，能力定位等价。

### 2.2 子 Agent 治理三件套：并发上限 / 会话限额 / 嵌套深度（v2.1.212 / 2.1.217 / 2.1.219）★ 重度 agent 用户必看

**含义**：三个版本合力给子 agent 加了防失控护栏——
- 并发子 agent 上限默认 **20**（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 可调，v2.1.217）
- 每会话子 agent 生成总数上限默认 **200**（`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`，`/clear` 重置预算，v2.1.212）
- 嵌套深度：先默认禁止嵌套（v2.1.217），再放开为**默认 3 层**（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`，v2.1.219）
- WebSearch 每会话上限默认 200（`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`，v2.1.212）

**好处**：防止"失控委派循环"和"失控搜索循环"烧 token；单条消息不能无界扇出后台 agent。

**与本机关系**：✅ 本机 ECC 规则要求并行 Task 执行、十几个自定义 agent，且已开启 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`。默认并发 20 对正常并行足够，限额是保险丝。若 workflow 编排需要更大扇出，用环境变量显式调高。

### 2.3 Dynamic workflow 默认中等规模 + workflowSizeGuideline 设置（v2.1.219）★ workflow 用户

**含义**：dynamic workflow 默认按「中等规模」指引生成（目标 < 15 个 agent）；新增 `workflowSizeGuideline` 设置键，可在任意 settings 文件里设定（设定后 `/config` 对应行隐藏）。

**与本机关系**：✅ 本机 `CLAUDE_CODE_WORKFLOWS=1` 且实际用过 workflow 编排。上篇提到的「Dynamic workflow size」从 `/config` 选项升级为可写进 settings 文件的键，便于固化。默认中等规模对省 token 友好。

### 2.4 /fork 改为后台会话，原用法拆给 /subtask（v2.1.212）

**含义**：`/fork` 现在把当前对话复制进一个**新的后台 session**（`claude agents` 里独立一行），你可以继续干别的；原来"在会话内起子任务"的行为改名为 `/subtask`。`/fork` 的副本还会创建自己的 worktree（v2.1.221），不再共用原 checkout。

**与本机关系**：✅ 重度后台 agent 用户直接受益：fork 出的分支工作变成可挂载、可并行、可删除的后台 job。注意操作习惯变化——想"临时分叉问个问题"用 `/subtask`，想"开并行副本"用 `/fork`。

### 2.5 MCP 长调用自动转后台（v2.1.212）

**含义**：运行超过 2 分钟的 MCP 工具调用自动转入后台，主会话保持可用。阈值/开关：`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`。

**与本机关系**：✅ 本机挂了 context7、drawio、pencil、paddle 等多个 MCP server，长调用（如 drawio 导出）不再卡住输入。

### 2.6 /code-review 改为后台子 agent 执行（v2.1.218）★

**含义**：`/code-review` 以后台子 agent 方式运行，审查过程不再灌满主对话上下文；堆叠 slash 命令时仍以这些命令为审查目标。

**与本机关系**：✅ 本机 ECC 规则要求"代码写完立即 code-reviewer"。升级后审查不占主上下文，配合 2.1.215 的行为变化（见 3.1）一起理解：审查从"自动触发"变为"手动 /code-review + 后台执行"。

### 2.7 /doctor 升级为完整体检 + 后台 agent 更新后自动热升级（v2.1.205 / 2.1.206）

**含义**：`/doctor`（别名 `/checkup`）从信息展示变成能诊断并修复问题的完整体检；新增检查项：建议裁剪已入库 CLAUDE.md 中模型可自行从代码推导的内容（v2.1.206）。另外 CLI 更新后，后台 agent 会在后台自动升级到新版本，不再等你 attach 时才慢速升级（v2.1.206）。

**与本机关系**：✅ 手动升级 CLI 后跑一次 `/doctor` 可自检环境。CLAUDE.md 裁剪检查对本机有参考价值（本机 CLAUDE.md 规则较多），但裁剪与否由用户决定。

### 2.8 屏幕阅读器模式（v2.1.208）

**含义**：新增 `claude --ax-screen-reader` / `CLAUDE_AX_SCREEN_READER=1` / `"axScreenReader": true`，纯文本渲染供读屏软件使用，后续版本持续改进了报读细节。

**与本机关系**：⚠️ 无障碍特性，本机当前无此需求，知道有即可。

## 3. 行为变化（影响使用习惯）

### 3.1 Claude 不再自动运行 /verify 和 /code-review（v2.1.215）★★ 重大

**变化**：Claude 不再自作主张跑 `/verify` 和 `/code-review` 技能，需要时由你显式调用。

**影响**：本机 ECC 规则（code-review.md）要求"代码写完/修改后必须审查"。升级后这条流程不会自动发生——需在 CLAUDE.md 规则里继续要求 Claude 主动调用，或自己手动 `/code-review`。这是**规则与内置行为的衔接点**，升级后建议验证一次审查流程仍然触发。

### 3.2 后台 session 的 git 提交策略变化（v2.1.221）★

**变化**：后台 session 仍会 commit + push 以保存工作，但**只在任务本身要求时才开 draft PR**；会遵循你 CLAUDE.md 里的 git 指示；结束时必报告工作成果所在位置。

**影响**：本机 CLAUDE.md 与 git-safe-* 技能对提交有明确约束（conventional commits、禁止破坏性操作）。升级后后台 agent 会读取并遵循这些指示，行为更可控。

### 3.3 hook `if:` 条件里单段 `dir/**` 匹配范围收窄（v2.1.214）★ 需自查

**变化**：hook `if:` 条件里的单段 `dir/**` 从"任意深度匹配"改为**只匹配 `<cwd>/dir`**；要任意深度匹配需写 `**/dir/**`。注意：`deny`/`ask` 权限规则不受影响，仍任意深度匹配。

**影响**：⚠️ 本机装有 ECC hooks（`ECC_DISABLED_HOOKS` 可见在管）。升级后应检查各 settings 里 hook 的 `if:` 条件是否用了单段 `dir/**` 写法，避免匹配范围悄悄变化。

### 3.4 `context: fork` 的 skill 默认后台运行（v2.1.218）

**变化**：frontmatter 带 `context: fork` 的技能默认转入后台运行；单个技能可用 `background: false` 退出。

**影响**：本机 200+ skill，若有 fork 型技能，交互节奏会变（后台跑完通知而非原地等）。

### 3.5 auto mode 不再从 `.claude/settings.local.json` 读配置（v2.1.207）

**变化**：仓库内的 `.claude/settings.local.json` 不再提供 `autoMode` 配置（安全考虑，仓库驻留文件不可信）；改用 `~/.claude/settings.json`。

**影响**：本机如在这些文件里配过 autoMode 需迁移。另（v2.1.222）Remote Control 的自动开启也收归用户级设置——repo 级 settings 只能关不能开。对本机（非官方 BASE_URL，Remote Control 本就禁用）影响很小。

### 3.6 「始终允许」权限规则保存到仓库根（v2.1.211）

**变化**：在 git worktree 里授予的"always allow"批准现在持久化到仓库根，跨 session、跨 worktree 生效。

**影响**：✅ 本机 update-all / speckit 等会创建临时 worktree，此前每个 worktree 要重新批准的痛点消除。

### 3.7 Task 工具的 `mode` 参数废弃（v2.1.212）

**变化**：`mode` 参数被忽略；子 agent 默认继承父 session 的权限模式。

**影响**：写 agent 编排提示词时不必再传 mode。

### 3.8 其他小变化

- **ultraplan 特性移除**（v2.1.222）。
- **agent 名禁止含 `:`**（v2.1.218）——`:` 保留给插件命名空间；本机自定义 agent 名均合规。
- **AskUserQuestion 自由文本回答措辞中性化**（v2.1.216）——你回答"先等等/先解释"时不再被错误转述为"继续"。
- **Claude in Chrome 会自动关闭用完的标签页**（v2.1.221）。⚠️ 本机规定网页浏览走 gstack /browse，此特性仅在不冲突时评估。
- **emoji 短代码补全**（v2.1.217，`emojiCompletionEnabled` 可关）；`/btw` 裸调用重开侧边问答面板（v2.1.212）。

## 5. 重要 bug 修复（挑本机有感项）

### 5.1 后台/agent 会话丢失 `ANTHROPIC_BASE_URL`，API key 发往默认端点报 401（v2.1.203）★★ 本机直接相关

**问题**：后台和 agent-view session 会丢掉 shell 导出的 `ANTHROPIC_BASE_URL`，请求发到官方默认端点并 401 失败——**等于网关凭证发错地方**。

**修复**：正确继承派发环境的 BASE_URL。

**与本机关系**：✅✅ 本机全部流量走 token-plan 代理（`ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`）。2.1.202 存在此问题，升级后后台 agent 的网关认证才可靠。这是**本次最值得升的修复**。

### 5.2 LLM 网关认证的后台 job 复活后「Not logged in」（v2.1.211）★★ 本机直接相关

**问题**：用 `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`（LLM 网关认证）的后台 job，被 daemon 重新拉起后显示"Not logged in"。

**修复**：网关认证在 daemon 重生场景下正确恢复。

**与本机关系**：✅✅ 本机认证方式恰好是 `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`，且重度使用后台 agent。与 5.1 配套，构成升级的核心动因。

### 5.3 自定义 `ANTHROPIC_BASE_URL` 网关上流式 idle 超时误触发（v2.1.222）★

**问题**：服务端 keep-alive ping 明明在线，流式 idle watchdog 仍在自定义网关上误触发中止。

**修复**：正确识别 wire 上的 keep-alive ping。

**与本机关系**：✅ 上篇提到本机依赖 watchdog（2.1.196 引入）防卡死；此修复让它在代理环境下不再误杀正常响应。另修复 HTTPS 代理后启动连通性检查挂起（改用与 API 请求相同的代理感知传输）。

### 5.4 PowerShell 5.1 权限绕过 + PowerShell 工具修复系列（v2.1.214）★ Windows 环境

**问题与修复**：
- **Windows PowerShell 5.1 会话存在权限检查绕过**——已修复（安全修复）
- `where.exe`/`fc.exe`/`diff.exe` 返回有效否定答案被误报为错误——已修
- `>`/`>>` 在 PS 5.1 下写出 UTF-16LE 文件导致其他工具读不了——已修
- 子进程等待 stdin 时命令挂到超时、Python 脚本读非 UTF-8 stdin 崩溃、非 ASCII 输出编码错误——已修

**与本机关系**：✅ 本机主 shell 是 PowerShell，且开了 `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`。权限绕过属安全问题，工具误报影响日常判断，均直接受益。

### 5.5 权限与安全修复批次（v2.1.212 / 2.1.214 / 2.1.221 / 2.1.222）★

**修复**：
- plan mode 会**不提示直接跑**文件修改类 Bash 命令（`touch`、`rm`）——已修（v2.1.212）
- 单段 `dir/**` 的 `Edit(src/**)` 类 allow 规则会错误放行树上任意位置的嵌套同名目录——已修（v2.1.214）

**与本机关系**：✅ 本机大量用 worktree、后台 agent 与 hooks，这批隔离/权限修复直接提升安全性。

### 5.6 内存泄漏与长会话性能系列（v2.1.208 / 2.1.216 / 2.1.217）★

**修复**：
