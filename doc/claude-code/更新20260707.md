## 2. 重点新特性详解

### 2.1 Claude Sonnet 5 默认模型 + 原生 1M 窗口（v2.1.197）

**含义**：Claude Sonnet 5 成为 Claude Code 默认模型，原生 1M token 上下文窗口，促销价 $2/$10 每百万 token（至 8 月 31 日）。需升级到 2.1.197+ 才能用。

**与本机关系**：⚠️ 本机通过 `ANTHROPIC_BASE_URL=https://coding.dashscope.aliyuncs.com/apps/anthropic` 走阿里 DashScope 代理，实际模型为 `qwen3.7-plus[1M]`，并非官方 Sonnet。**此特性对本机无直接效果**——`/model` 里的 Sonnet 5 选项只在直连官方 API 时生效。但本机已有 1M 窗口（`autoCompactWindow=750000`），能力等价。

### 2.2 子 Agent 默认后台运行（v2.1.198）★ 重度 agent 用户必看

**含义**：主 Claude 启动子 Agent 后**不再阻塞等待**，而是继续干别的活，子 Agent 完成后通知主 Claude。此前是渐进式灰度，2.1.198 正式默认。

**好处**：
- 主循环不再被慢子 Agent 占住，吞吐提升
- 多个独立子 Agent 可并行，主 Claude 同时推进其他任务
- 配合本机 CLAUDE.md 的「并行 Task 执行」规则（agents.md），天然契合

**示例**：本机 agents.md 要求「安全分析 + 性能审查 + 类型检查」3 个 agent 并行。升级后主 Claude 派出 3 个后台子 Agent 后可继续写代码或回复，子 Agent 回来再汇总。

**配套**：2.1.198 还新增 `Notification` hook（`agent_needs_input` / `agent_completed`），后台 agent 需要输入或完成时触发。

### 2.3 后台 Agent 自动 commit / push / 开 draft PR（v2.1.198）

**含义**：从 `claude agents` 启动的后台 agent，在 worktree 里完成代码工作后，**自动 commit、push 并开 draft PR**，而不是停下来问。

**好处**：后台 agent 真正变成「无人值守的代码工人」——派活→干完→提 PR，全程不需人工介入。

**与本机关系**：本机有 `git-safe-push` / `git-merge-main` 等安全 git 技能，且 git user 已配置（hehe9771）。升级后后台 agent 可直接产出 PR。注意确认默认分支策略（本机主分支为 `main`）。

### 2.4 堆叠 slash-skill 调用（v2.1.199）★ 重度 skill 用户

**含义**：`/skill-a /skill-b do XYZ` 这样的写法现在会**同时加载前 5 个 skill**，而不是只加载第一个。

**好处**：可组合多个 skill 协同。例如本机可 `/superpowers:brainstorming /frontend-design 实现一个数据看板`，先走头脑风暴流程再进入前端实现。

**与本机关系**：本机装了 200+ skill（update-all 技能统计），堆叠调用能解锁组合玩法。

### 2.5 /rewind 恢复 /clear 前的对话（v2.1.191）

**含义**：`/rewind` 现在可以回到 `/clear` 之前的对话状态。

**好处**：`/clear` 不再是单行道。误清空后可找回上下文。本会话开头就执行了 `/clear`，升级后这类操作可回退。

### 2.6 Dynamic workflow size 设置（v2.1.202）★ 本会话用过 workflow

**含义**：`/config` 新增「Dynamic workflow size」设置（小/中/大 agent 数量），控制 Claude 生成 dynamic workflow 的规模倾向。是**建议性指引，非硬性上限**。

**与本机关系**：本会话刚执行过 update-all 的 workflow 式编排，且 ECC 规则有 workflow 编排相关内容。此设置可调小 workflow 规模以省 token，或调大以追求覆盖度。

**配套**：2.1.202 还给 workflow 加了 `workflow.run_id` 和 `workflow.name` 两个 OTel 属性，便于从遥测数据重建 workflow 运行轨迹。

### 2.7 /dataviz 内置技能（v2.1.198）

**含义**：新增内置 `/dataviz` skill，提供图表与仪表盘设计指导，带一个可运行的调色板校验器。

**与本机关系**：本机有 `data-analysis` / `pandas-data-analysis` 技能，`/dataviz` 是官方补充，做数据可视化时可直接调用。

### 2.8 bash 模式文件路径自动补全（v2.1.193）

**含义**：在 bash 模式（`!` 前缀输入）里，文件路径支持实时自动补全。

**好处**：本机用 `! <command>` 跑 shell 命令时，输路径不用手敲全名。

### 2.9 鼠标点击选择菜单 + 可点击文件附件（v2.1.191 / 2.1.196）

**含义**：全屏模式下，权限提示、`/model`、`/config` 等选择菜单支持鼠标点击选择（2.1.191）。聊天里的文件附件支持 Cmd/Ctrl-click 在 Finder/Explorer 里定位（2.1.196）。

**与本机关系**：Windows 环境下 Ctrl-click 定位文件实用。

### 2.10 auto-mode 拒绝原因可见（v2.1.193）

**含义**：auto 权限模式拒绝命令时，原因会写入 transcript、拒绝 toast 和 `/permissions` 的近期拒绝列表。新增 `autoMode.classifyAllShell` 设置，可把所有 Bash/PowerShell 命令都过 auto 分类器（而非只拦任意代码执行模式）。

**与本机关系**：本机有大量权限规则（ECC rules、update-all 黑名单），拒绝原因可见便于排查为什么某命令被拦。

### 2.11 组织默认模型（v2.1.196）

**含义**：管理员可在组织控制台设默认模型，用户未自选时 `/model` 显示「Org default」。

**与本机关系**：⚠️ 走 DashScope 代理，组织模型概念不直接适用。

### 2.12 Claude in Chrome GA（v2.1.198）

**含义**：Claude in Chrome 正式可用（GA）。

**与本机关系**：⚠️ 本机 CLAUDE.md 规定「所有网页浏览均使用 gstack 的 /browse 技能，禁止使用 chrome_devtools 工具」。Claude in Chrome 与该规则有潜在冲突，需评估是否启用。

## 3. 行为变化（影响使用习惯）

### 3.1 default 权限模式改为 Manual（v2.1.200）★★ 重大

**变化**：CLI、`--help`、VS Code、JetBrains 各处的「default」权限模式统一改名为「Manual」。`--permission-mode manual` 和 `"defaultMode": "manual"` 仍兼容 `default` 写法。

**影响**：配置文件里写 `"defaultMode": "default"` 仍生效（兼容），但 UI 显示为 Manual。建议配置逐步改名以保持一致。

### 3.2 AskUserQuestion 不再自动继续（v2.1.200）

**变化**：`AskUserQuestion` 对话框默认不再自动继续，需 `/config` 开启 idle 超时才自动继续。

**影响**：本机 ECC 工作流常用 AskUserQuestion 澄清需求，升级后这类提问会停下等用户，不再自动推进。如想保持自动继续，去 `/config` 开 idle timeout。

### 3.3 /review 改回单次快速审查（v2.1.202）

**变化**：`/review <pr>` 改回单次快速审查；多 agent 审查改用 `/code-review <level> <pr#>`。

**影响**：本机有 `/review` 和 `/code-review` 两个 skill。升级后两者职责分离：`/review` 快、`/code-review` 深。

### 3.4 Remote Control 在非 Anthropic BASE_URL 下禁用（v2.1.196）★ 与本机直接相关

**变化**：当 `ANTHROPIC_BASE_URL` 指向非 Anthropic 主机时，Remote Control 自动禁用，与 `CLAUDE_CODE_USE_BEDROCK`/`_VERTEX`/`_FOUNDRY` 行为一致。

**与本机关系**：✅ 本机 `ANTHROPIC_BASE_URL` 指向 DashScope，Remote Control 会被禁用。这是预期行为——本来就不用官方 Remote Control。不影响正常使用。

### 3.5 移除 /agents 向导（v2.1.198）

**变化**：`/agents` 向导移除。创建/管理子 agent 直接让 Claude 做，或手动编辑 `.claude/agents/`。

**与本机关系**：本机 `.claude/agents/` 已有 planner/architect/code-reviewer 等十几个 agent 文件，本来就是手动维护，移除向导无影响。

### 3.6 打开 agents view 改为单次 ←（v2.1.196）

**变化**：从前台 session 打开 agents view 从按两次 `←` 改为按一次。

### 3.7 streaming idle watchdog 默认开启（v2.1.196）

**变化**：流式响应 5 分钟无事件则中止并重试，所有 provider 默认开启。`CLAUDE_ENABLE_STREAM_WATCHDOG=0` 可关。

**与本机关系**：走 DashScope 代理，偶有慢响应，此 watchdog 可防止卡死。建议保持开启。

### 3.8 Sonnet 5 session 不再用 mid-conversation system role（v2.1.201）

**变化**：Claude Sonnet 5 session 不再使用对话中途插入 system role 的方式传递 harness 提醒。

**与本机关系**：走 qwen 代理，此变化对 qwen 调用无直接效果。

## 4. 新增设置与环境变量

| 版本 | 设置/变量 | 作用 |
|------|-----------|------|
| 2.1.202 | `/config` Dynamic workflow size | 控制 workflow 规模倾向（小/中/大，建议性） |
| 2.1.200 | `/config` AskUserQuestion idle timeout | 让提问对话框空闲超时后自动继续 |
| 2.1.199 | `CLAUDE_CODE_RETRY_WATCHDOG` | 非容量瞬态错误默认重试 300 次，取消 `CLAUDE_CODE_MAX_RETRIES` 的 15 上限 |
| 2.1.196 | `CLAUDE_ENABLE_STREAM_WATCHDOG` | 流式 idle watchdog 默认开，设 `=0` 关闭 |
| 2.1.195 | `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` | 全屏模式禁用鼠标点击/拖拽/悬停，保留滚轮 |
| 2.1.193 | `autoMode.classifyAllShell` | 所有 Bash/PowerShell 命令过 auto 分类器 |
| 2.1.193 | `OTEL_LOG_ASSISTANT_RESPONSES` | OTel 记录模型响应文本；默认跟随 `OTEL_LOG_USER_PROMPTS`，设 `=0` 保持只记 prompt |
| 2.1.193 | `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP` | 关闭后台 shell 内存压力回收 |

**安全提醒**：2.1.193 的 `OTEL_LOG_ASSISTANT_RESPONSES` 默认跟随 prompt 日志策略——如果部署已开 `OTEL_LOG_USER_PROMPTS`，升级后会开始记录模型响应内容。需保密响应的设 `OTEL_LOG_ASSISTANT_RESPONSES=0`。

## 5. 重要 bug 修复（挑本机有感项）

### 5.1 重新调用已加载 skill 不再重复追加指令（v2.1.202）★ 重度 skill 用户

**问题**：重复调用一个已加载的 skill，会往上下文里追加一份重复指令，污染上下文、浪费 token。

**修复**：不再重复追加。

**与本机关系**：本机 200+ skill，update-all / ECC 等技能常被反复触发，此修复直接减少上下文污染。

### 5.2 PowerShell git diff/grep exit 1 不再误报失败（v2.1.196）★ Windows 环境

**问题**：PowerShell 下 `git diff`/`git grep`、`egrep`/`fgrep`、含 `|` 的引号搜索模式在 exit 1 时被报为失败，与 Bash 行为不一致。

**修复**：exit 1 不再误报，与 Bash 对齐。

**与本机关系**：✅ 本机主 shell 是 PowerShell，update-all 等技能脚本里大量 `grep -q` 判断，此修复减少误判。

### 5.3 hook matcher 带连字符精确匹配（v2.1.195）★ 本机有 code-reviewer 等

**问题**：带连字符的 hook matcher（如 `code-reviewer`、`mcp__brave-search`）被错误地子串匹配。

**修复**：精确匹配。要匹配某 MCP 所有工具用 `mcp__brave-search__.*`。

**与本机关系**：本机 agent 名带连字符（`code-reviewer`、`security-reviewer`、`build-error-resolver`、`refactor-cleaner` 等），hook 配置不再误触发。

### 5.4 后台 session 睡眠唤醒后不再静默停止（v2.1.200）

**问题**：后台 session 在睡眠/唤醒或重开卡住 session 后会中途静默停止；Esc 取消的 turn 在卡住重开后会重跑；daemon.lock 的 PID 被 OS 复用导致后台 agent 永不启动。

**修复**：三项都修。

**与本机关系**：Windows 笔记本睡眠唤醒常见，此修复直接提升后台 agent 稳定性。

### 5.5 恢复多 worktree 仓库 session 不再耗时耗内存（v2.1.202）

**问题**：在多 git worktree 仓库里按名字恢复 session 或打开恢复选择器，会耗时几分钟且吃大量内存。

**修复**：优化。

**与本机关系**：本机 update-all 技能、ECC 等会创建临时 worktree，多 worktree 场景此修复有感。

### 5.6 唤醒后台 job 不再误删对话（v2.1.196）

**问题**：唤醒后台 job 时，如果 transcript 探测误读真实 transcript，会**永久删除对话并重跑原始 prompt**。

**修复**：可疑 transcript 文件移到一边，绝不删除。

**与本机关系**：后台 agent 跑长任务时此修复避免灾难性丢会话。

### 5.7 网络瞬断 / SSL 错误重试改进（v2.1.198 / 2.1.199）

**修复**：mid-response 的 ECONNRESET 等瞬态错误改为退避重试而非直接失败；SSL 证书错误（TLS 拦截代理、缺 `NODE_EXTRA_CA_CERTS`、证书过期）不再烧重试次数，立即给出可操作提示；流式响应中途 overloaded 错误保留已输出部分并标注「结果不完整」。

**与本机关系**：走 DashScope 代理，网络瞬断重试改进直接提升稳定性。

### 5.8 子 agent 被限流截断返回部分结果（v2.1.199 / 2.1.200）

**问题**：子 agent 被限流或服务器错误截断时静默失败，或返回空结果，或把 API 错误误报为成功。

**修复**：返回部分工作成果给父 agent，并正确上报错误。

**与本机关系**：重度 agent 用户，此修复让并行 agent 更可靠。

### 5.9 流式响应滚动跳到底部修复 + CPU 降 37%（v2.1.191）

**修复**：读历史输出时流式响应不再把视图拉到底部；流式文本更新合并到 100ms，CPU 降约 37%，长 session 内存增长减缓。

### 5.10 installer 下载 proxy 断连重试（v2.1.202）

**修复**：installer/updater 下载遇 proxy 中途断连不再立即「aborted」失败，改为重试。

**与本机关系**：下次手动升级 CLI 时，网络不稳也能续传。

## 7. 升级建议

### 7.1 是否升级

**建议升级**。2.1.187 → 2.1.202 中对本机有明确价值的更新较多：
- 子 Agent 默认后台运行（2.1.198）契合本机并行 agent 工作流
- skill 重复加载修复（2.1.202）、堆叠 skill（2.1.199）契合重度 skill 用法
- PowerShell exit 1 修复（2.1.196）、后台 shell handoff 契合 Windows 环境
- 后台 agent 稳定性系列修复（2.1.200）契合睡眠唤醒场景

与本机无直接效果的 Sonnet 5 / 组织模型 / Remote Control 不影响现有 DashScope 接入。

### 7.2 升级方法（手动，因黑名单不自动更新）

```bash
# 本机 DISABLE_AUTOUPDATER=1，daemon 不会自动更新 CLI，需手动：
npm install -g @anthropic-ai/claude-code@latest

# 验证
claude --version   # 应显示 2.1.202
```

### 7.3 升级后必做

1. **重启 Claude Code daemon**，使新版本生效
2. 检查 `~/.claude/settings.json` 的 `env` 段：
   - `DISABLE_AUTOUPDATER=1` 仍保留（本机刻意关闭自动更新）
   - 如开了 `OTEL_LOG_USER_PROMPTS`，按需设 `OTEL_LOG_ASSISTANT_RESPONSES=0` 避免记录响应内容
3. 权限模式配置：`"defaultMode": "default"` 仍兼容，但建议逐步改名为 `"manual"` 与新 UI 一致
4. 如想用 AskUserQuestion 自动继续，去 `/config` 开 idle timeout
5. update-all 技能黑名单保持不动（`@anthropic-ai/claude-code` 不自动更新是本机既定策略）

### 7.4 不升级的风险

- 继续遇到 skill 重复加载污染上下文（2.1.202 修复）
