### 同日追加：6 Command 部署 + 21 依赖插件

- 根因确认：pm-skills 市场的 6 个 Command（discover/strategy/write-prd/plan-roadmap/prioritize/leadership-transition）在仓库 `commands/` 目录但**不属于任何插件**（77 个插件 source 全是 `./skills/<name>`），装满市场也敲不出命令。

### 踩坑与根因（已固化进 update-all v2.2.0 预检，详见 references/plugin-pitfalls.md）

| # | 坑 | 根因 | 固化措施 |

| 2 | enabledPlugins 死条目误导（8 个 pm-* 看似启用实未装） | 启用标记 ≠ 安装；`claude plugins install` 失败/市场缺失也会留 true | Phase 2 对账同时检测：enabled 但未装 → WARN + 给清理命令 |
| 3 | 市场名撞车：phuryn/pm-skills 与 deanpeters/Product-Manager-Skills **同名 `pm-skills`**，本机市场指向 deanpeters，phuryn 8 个插件永远装不上 | Claude Code 市场名全局唯一，add 同名不警告 | 对账报告列出"enabled 未装"时标注可能为撞名；更换来源须先 `marketplace remove` |
| 4 | commands 装不出来：commands/ 目录不随插件分发 | 上游 77 插件 source 均为单技能目录，commands/ 无人认领 | 登记表注记；此类仓库须手动复制 commands/*.md 到 ~/.claude/commands/ |
| 5 | 装完"找不到"（技能/命令不可见） | 插件组件在**会话启动时**快照加载，运行中会话不热加载 | 技能注意事项已有"重启/reload-plugins"，本次实测 /reload-plugins 立即生效 |

## 2026-09-18（晚）：用户级命令收敛——移除 94 个 ECC 衍生副本 + 坑 7 固化（update-all v2.4.0）

### 背景

排查 `/e2e` 命令来源时发现：`~/.claude/commands/` 112 个命令中 **94 个与 ECC 插件 commands/ 逐一重名**（历史上手动复制，脱离插件版本管理）。后果：插件升级不同步副本（已分叉）、裸名与 `/ecc:` 前缀同名双套行为。

### 核验数据（执行前逐项验证）

- 用户级 112（顶层平铺）｜ECC v2.2.1 `commands/` 递归 94｜重名交集 94｜用户独有 18
- MD5 逐对比对：**93 完全一致** + react-test 差异为旧版相对路径残留（`../rules/react/` vs 插件版 `../rules/ecc/react/`，非用户自定义）→ 94 个全部可移除
- 保留侧 19 文件对被移除名的"引用"逐一核实：全部为普通词/帮助文本（claw 的 `/sessions` 是其内部子命令），**无真实斜杠依赖**
- 跨插件扩展检查：其余插件无与用户命令重名的真实 commands（初步"103 重名"系插件缓存内 `docs/*/commands` 文档副本与 node_modules 干扰，已排除）
- 事实订正：installed_plugins.json 权威源结构为顶层 `{version, plugins}`，插件条目在 `.plugins` 下（直接 `.'ecc@ecc'` 取不到）

### 执行

| 步骤 | 操作 | 结果 |
|---|---|---|
| ① 备份式移除 | 94 个文件 **Move** 至 `~/.claude/commands-backup-ecc-20260918/`（含 MANIFEST.md 新旧对照表），恢复=移回 | ✓ |
| ② 保留 | 18 个用户独有命令（git 安全三件套、PM 6 命令、claw/devfleet、零散自建 docs/e2e/eval/tdd/verify/orchestrate/prompt-optimize） | ✓ 剩余数=18 校验通过 |
| ③ 固化 | update-all v2.3.0 → **v2.4.0**：Phase 2 新增坑 7 命令重名检测（用户 commands × 已装插件 commands 交集 → WARN）；坑 7 进 references/plugin-pitfalls.md；历史变更记录拆分至 `update-all/references/CHANGELOG.md`（SKILL.md 守住 1000 行上限） | ✓ |

### 生效与行为变化

- `/reload-plugins` 或重启后：裸名命令仅剩 18 个；原 94 个改用 **`/ecc:<name>`** 调用（如 `/ecc:code-review`、`/ecc:plan`）
- 注意：`/e2e`、`/tdd`、`/verify` 等独有命令不受影响，仍是用户级定义

### 当晚二阶段：退役命令副本清理（用户指令直删，无备份）

> 本节更正上文"② 保留 18 个用户独有命令"的结论：复查 `/e2e` 是否最新后发现，18 个中有 **9 个实为上游退役命令遗留**。

- **根因**：上游把旧命令体收编为技能（"collapse legacy command bodies into skills"），`legacy-command-shims/commands/` 留 12 个退役垫片。实例核实 `/e2e`：上游 main 已无 `commands/e2e.md`，功能由 `ecc:e2e-testing` 技能承接，仅存 23 行兼容垫片（"Prefer the skill directly"）；用户副本停留在 2026-03-29 代（358 行完整旧版）。e2e-runner 代理用户级与插件版 MD5 一致（最新），仅命令 prompt 过时。
- **涉及 9 个**：e2e、tdd、verify、eval、docs、claw、devfleet、orchestrate、prompt-optimize
- **处置（用户明确指令：不备份直删）**：Remove-Item 直删；剩余用户命令 = **9**（git 三件套 + PM 6：discover、prioritize、strategy、write-prd、plan-roadmap、leadership-transition）
- **update-all 同步升级**：坑 7b 退役命令自动清理——新增 `references/cleanup-retired-commands.sh`（用户命令名 ∈ 上游 legacy shims 且与退役前版本逐字节一致 → 自动移除并记日志；不一致 → WARN 留人工），Phase 2 对账块挂载，每轮自动执行
- **替代调用**：`/ecc:e2e-testing`、`/ecc:tdd-workflow` 等插件技能（每轮随插件自动更新）
