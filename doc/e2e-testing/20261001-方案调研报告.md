# Web E2E 测试方案调研报告：Claude Code 对标 Codex

> 日期：2026-10-01 | 调研方式：3 个并行联网调研 agent | 来源：40+（全部经抓取原文验证，剔除搜索幻觉）
> 背景诉求：Web 应用移动仿真 E2E——真实操作禁 mock、模拟器前台可见不影响其他程序、测试用例自动编写、高覆盖率

---

## 一、结论摘要

1. **"Codex 一句提示词自动做 E2E"不成立为开箱能力**：Codex 的内置浏览器只存在于 ChatGPT 网页版/桌面 app，官方文档原文 "Browser isn't available in Codex CLI or the CodIDE extension"；官方反而告诫 "Keep each browser task small enough to review in one pass"。
2. OpenAI 内部做到"代码变更+真实验证一体"靠**自建 harness**（app 按 worktree 可启动 + CDP 接入 agent runtime + DOM snapshot skills），非开箱即用。
3. **两边默认都不带**浏览器验证环境；社区共识 "Give Claude/Codex a way to verify its own work"。体验差异的真正来源：Codex 把验证环境**封装在 app 产品里**，Claude Code 需要用 playwright-cli/MCP **组装**——而组装件（playwright-cli 官方 agent 工作流）已存在且更强。
4. 微软官方 2026 路线就是给 coding agent 的：playwright-cli（"If you are using coding agents, that is the best fit"）+ Playwright Test Agents（1.56+，planner→generator→healer）。
5. 非侵入前台无硬障碍：CDP 注入事件不占宿主鼠标键盘；Playwright `launch()` 默认已带三个防节流 flags，窗口遮挡/最小化不失真；抢焦点仅发生在新建页面瞬间。

## 三、Claude Code 侧工具链（调研确认）

- **playwright-cli**（microsoft/playwright-cli，13.7k stars，npm 0.1.22）：官方定位 coding agent 最佳载体，token 高效（不把整页数据塞给 LLM）；`playwright-cli install --skills` 即本机已装的技能来源。
- **Playwright Test Agents**（1.56+，playwright.dev/docs/test-agents）：`npx playwright init-agents --loop=claude` 生成 planner→generator→healer 三 agent；generator "verifies selectors and assertions live as it performs the scenarios"；healer 判产品真 bug 时标 skip 而非硬修（防假绿）。本机 Playwright 1.60 已验证支持。
- **Playwright MCP**（37.7k stars）：README 明确推荐 agent 用 CLI+skills（更省 token），MCP 留给需持久状态的探索/自愈循环；testing caps（browser_generate_locator、browser_verify_*）与 --codegen 可用。
- **chrome-devtools-mcp**（52.8k stars）：定位"查为什么挂"（CWV trace、网络、console source-mapped 堆栈），与 playwright 互补；注：本机用户规则禁用 chrome_devtools MCP（网页浏览场景），测试排查若需用须用户先解禁。
- AI 运行时操作类工具（Midscene.js 15k stars 活跃、TestZeus Hercules 481 stars）：AI 直接操作不生成可维护测试代码，不符合"自动编写测试用例沉淀"诉求，仅备选；auto-playwright/ZeroStep 已停滞/弃更。
- 社区 run-until-green 工作流（Medium/testsmith.io 等）与官方 agents 同构：探索→记录选择器→写 spec→跑→结构化错误喂回→只修测试→上限迭代。

## 四、非侵入前台与节流（Windows 11）

| 结论 | 依据 |
|---|---|
| CDP 注入输入是浏览器内部合成（Input.dispatchMouseEvent 系），不占宿主鼠标键盘、不依赖窗口焦点 | Puppeteer #14682 / Playwright #1635 / ChromeDriver 文档 |
| 抢焦点仅"新建页面/窗口"瞬间 OS 级激活；官方 2026-06 修复后 2026-07 回退，issue #41306 open，暂无解 | Playwright PR #41430、#41734 |
| **Playwright `launch()` 默认已传齐三个防节流 flags**（--disable-background-timer-throttling / --disable-backgrounding-occluded-windows / --disable-renderer-backgrounding），硬编码于 chromiumSwitches.ts | Playwright 源码 |
| connectOverCDP 复用已有 Chrome 时 flags 由用户启动参数决定，须自己补 | 同上 |
| Chrome 121+ Windows：被遮挡/屏幕外/最小化/跨虚拟桌面均判 occluded → 节流；launch 默认 flags 已兜底 | Chromium bug 1092277、content_switches.cc |
| 摆放优先级：副屏角落 > 主屏边缘 > 虚拟桌面；不要最小化（可观察性） | 综合 |

## 五、代码覆盖率

- **monocart-reporter**：V8 模式（免插桩、Chromium only、source map 还原）/ Istanbul 模式（`@swc/plugin-istanbul` 预插桩、全浏览器）双模式；有 Next.js 示例仓库 cenfun/nextjs-with-playwright（第三方）。
- Playwright 原生 Coverage API（startJSCoverage）官方标注 Chromium-only。
- Playwright codegen 无 headless（源码确认），依赖真人录制，不适合 agent 路线（我们不用它）。

## 六、已落地方案（2026-10-01）

1. 新技能 `~/.claude/skills/web-e2e/SKILL.md`：playwright-cli plan→generate→heal + 官方 agents 循环 + 五条铁律（禁 mock / 先看后写 / 断言即业务 / 失败只许 heal / 不许静默）+ 覆盖矩阵（6 类强制下限）+ 非侵入前台配置 + monocart 覆盖率。
2. 启动方式：功能做完一句 `/web-e2e 测试「XX」功能 <URL>，移动仿真，禁 mock，跑绿出报告`；首次每项目跑 `npx playwright init-agents --loop=claude --project=mobile-chrome`。
3. 本机资产：playwright-cli 0.1.20（npm 最新 0.1.22，按组件约束未经同意不升）+ Playwright 1.60.0。
